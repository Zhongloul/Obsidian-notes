CIS建立连接过程详解

最近公司的项目要在蓝牙耳机加入BLE Audio(CIS)的支持，我承担了此项艰巨任务。下面从手机侧抓取的btsnoop的HCI层来分析LEA-CIS的连接建立过程，从LE连接建立到LEA Service查询，再到音乐起播建立CIS连接：

1：手机和耳机建立LE连接和SMP加密结束后，进入LEA ATT服务的查询，这是一个漫长的过程：

a:首先发起primary service查询，从下面HCI log能看到基本的LE audio服务，包括VCS，CSIP，CAP，BAP，PAC，MCP,CCP等，耳机是支持的。

b:继续查询以上服务的特质值和句柄，以及写入CCC订阅相关特征值，通过写入通告(Notification)激活相应特征值的主动通告功能:

c:以上服务查询基本结束，开始ATT读取服务的具体内容：

比如支持CSIP服务，设备的size等于2两个，说明这个协调集有两个设备，即左右耳机（关于CSIS服务以后再讲）。

2：以上服务查询过程结束之后，手机会建立6个EATT连接，分别是call control point service(CCP)，Media control service(MCS)，voice control service(VCS)，Coordinate Set Identify Service(CSIP)，Published audio capability Service(PACS)，Audio stream control service(ASCS)。

CCP：通话控制服务，如来电响铃，接通，三方会话等等。

MCS：媒体控制服务，主要涉及播放音乐的一些操作，如起播，停止，暂停，上一首下一首，还有歌词等。

VCS：音量控制服务，用于调节播放音乐的音量。

CSIP：设备协议集服务，用于同一个设备协议集的定义连接等，比如手机在识别到同一个设备协调集的两个耳机，主耳配对后，手机会自动发起副耳的配对。

PACS：公共音频能力服务，就是对外公布支持哪些音频场景，比如游戏，媒体，音频助手等，以及位置，还有编解码器参数等等。

ASCS：音频流控制服务，就是音频流的一些控制，比如endpoint查询，编码器参数的配置等，类似于A2DP的stream control。
