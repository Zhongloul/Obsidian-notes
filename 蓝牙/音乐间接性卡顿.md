
排查耳机播放采样率是否和音源一致

session 1 的两个速率都是从 L log 里直接数时间戳和 seq 算的，方法跟 session 2 完全一样：

## 1. rd \= 23.14ms/包

取正常播放段首尾两个 rd 事件（log 行 360 → 行 543）：

```
(17:10:11:122) rd:0349(00004099,00004099)
(17:10:13:274) rd:03a6(00004381,00004381)
```

seq 差 \= 0x3A6 − 0x349 \= 0x5D \= ​**93 包**​，时间跨度 \= 2152ms

```
2152ms ÷ 93 包 = 23.14ms/包
```

## 2. rx \= 23.14ms/包

同期 rx 首尾（行 361 → 行 532）：

```
(17:10:11:138) rx:0353(000040e9,0000409f), 08,00ac, 274
(17:10:13:059) rx:03a6(00004381,00004336), 08,00ac, 32
```

seq 差 \= 0x53 \= ​**83 包**，跨度 1921ms

```
1921ms ÷ 83 包 = 23.14ms/包
```

两个速率​**完全相等**，这就是"匹配"的依据——rd 播放节拍与 rx 到达节拍一致，播放时钟没有比源快。

## 3. "无欠载"的判定

- 整段 2.15s 内​**没有一次 bypas**（session 2 每 2.5s 必有一次）；
- 缓冲深度稳定：11:138 时刻 rx 领先 rd 恰好 10 包（0x353−0x349\=0xA），13:059 手机发完最后一包时 rd 在 039d 附近，缓冲还是 \~10 包，2 秒内没有收缩趋势；
- 唯一一次 `a2dp empty`​ (13:289) 之前 158ms 是 `avdtp_end_of_play 0:hdl 80`​ (13:131)——手机停流后 rx 不再有新包，rd 把剩余缓冲自然放完（13:059 后 rd 又放了 039d\~03a6 共 10 包约 200ms，指针 w−r 归零），属于流结束排空，不是 rx 跟不上。

## 4. "44.1kHz"的交叉验证

23.14ms ≈ 1024 samples ÷ 44100Hz \= 23.22ms（一包 \= 8 帧 × 128 样本）。同一包结构下 session 2 的 21.33ms ≈ 1024 ÷ 48000。两个数都落在标准采样率节拍上，且 session 1 里 rd 与 rx 相等，说明该阶段播放时钟与源同为 44.1kHz。

补充一句诚实边界：`00ac`​/`00ca` 是 rx 行里的一个参数字段，具体含义在预编译库（liba）里，源码里查不到定义，我拿它当"两个会话参数确实不同"的旁证，主证据是上面的时间节拍。
